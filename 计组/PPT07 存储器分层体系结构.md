# PPT07 存储器分层体系结构

## 一、 

- 现代计算机用分层结构：越靠近 CPU 越快、越小、越贵；越远离 CPU 越慢、越大、越便宜。
- 寄存器（CPU内，速度最快容量最小）、Cache（位于CPU内部/附近）、主存（DRAM）、外存（容量大，速度慢）
- 基本术语：
  - **记忆单元cell**：0/1 （存储基元）
  - **存储单元/编址单位**：有同一个地址的一组位
  - 存储单元组成的阵列 -> **存储体bank**
  - MAR:存储器地址寄存器，放主存地址
  - MDR：存储器数据寄存器，放从主存读出的数据或准备写入主存的数据
- 主存地址空间大小不等于实际主存容量
  - 地址空间是 CPU/体系结构能表示的范围，实际容量是装了多少存储芯片。
- 存储器分类
  - RAM（随机存储器，eg.内存，每个单元理论访问时间一样）
  - SAM（顺序存取，磁带）
  - DAM（直接存取，磁盘，先定位再顺序读写）
  - CAM（相联存储器，快表TLB，按内容）
- 按断电后信息是否保留分类
  - 易失性：断电后信息丢失
    - RAM、Cache
  - 非易失性：断电后信息仍保留
    - ROM、Flash、磁盘、光盘
  - 易错点：
    - “非易失”不等于“高速可随意改写”
    - Flash 虽然可擦写，但写入前常要先擦除，且写速度通常慢于读速度
- 主存和外存的分工
  - 主存直接和 CPU 交换信息
  - 程序执行前，代码和数据先从外存（长期保存程序和数据）调入主存；
  - CPU 真正执行的是主存中的指令流
- 主存性质：
  - 存储容量
    - B、KB、MB、GB
    - 若按字节编址，容量 = 可编址单元个数 × 1B
    - 若按字编址，就要看一个字有多少位
  - 存取时间 `T_A`（可分读操作和写操作）
    - 从启动一次存储器操作开始，到该操作完成所需的时间
  - 存储周期 `T_MC`
    - 一次访问完成后，存储器内部电路往往还需要恢复，因此不能立刻开始下一次访问
    - 一般有：`T_MC > T_A`
- RAM：SRAM 与 DRAM
  - 半导体主存主要是 RAM（SRAM 、 DRAM）
  - SRAM（Static RAM，静态随机存储器）
    - 存储单元通常由 6 个晶体管构成，类似双稳态触发器
    - 只要不断电，状态就能稳定保持
    - 读出不是破坏性读出，不需要读后重写
    - 典型用途：Cache
  - DRAM（Dynamic RAM，动态随机存储器）
    - 存储单元通常由 1 个晶体管 + 1 个电容构成
    - 信息靠电容上的电荷保存，但电荷会逐渐泄漏，因此需要**周期性刷新**
    - 读出通常是**破坏性读出**，读后需要再生
    - 典型用途：主存
    - 按**行**刷新，在总时间中占比不大
      - 若共有 4096 行，需要在 64ms 内全部刷新完,则每行最大刷新间隔为：$64ms / 4096 = 15.625us$
  - 为什么 Cache 用 SRAM、主存用 DRAM
    - Cache 容量相对小，但追求极高速度，所以选 SRAM
    - 主存容量要大，如果全用 SRAM 成本太高，所以用 DRAM
- 同步 DRAM、DDR 和突发传送
- ROM（Read Only Memory，只读存储器）
  - 断电后信息不丢失，非易失性存储器
  - 主要用于存放相对固定、掉电后也必须保留的程序或数据
  - Flash：块擦除、可重写、读快写慢(写之前往往要先擦除,读速度通常快于写速度)

## 二、

- CPU 怎么访问主存
  - CPU通过总线和存储控制器发起一次读写
  - 总线：
    - 地址线：告诉主存访问哪个地址
    - 数据线：传送读出的数据或待写入的数据
    - 控制线：说明本次是读还是写，并给出相关时序控制

- 存储器芯片扩展
  - 单个存储芯片容量有限，所以要把多个芯片组合成所需的主存
    - 字扩展：位数不变，地址数变多
    - 位扩展：地址数不变，位数变多
    - 字位同时扩展：地址数和位数都扩
- 字扩展
  - 这种方式的特点是：先把一片芯片的地址用完，再用下一片
- 位扩展
  - 所以需要 8 片并联，每片提供 1 位
  - 所有芯片接收同一组地址，同时输出各自那一位，拼成一个 8 位数据
  - 这时各芯片地址范围完全相同，只是分别对应数据总线上的不同位
- 字位同时扩展
  - 例：用 `16K x 4位` 芯片构成 `64K x 8位` 存储器
  - 容量方向：`64K / 16K = 4`
  - 位宽方向：`8 / 4 = 2`
  - 所需芯片数：`4 x 2 = 8`
    - 芯片数 = 字方向扩展倍数 x 位方向扩展倍数
- 做芯片扩展题的套路
  - 先看目标存储器的“字数”和“位数”
  - 再看单片芯片的“字数”和“位数”
  - 分别求出容量方向和位宽方向各要扩多少倍
  - 最后判断哪些地址位送芯片内部（单芯片地址数），哪些地址位用于片选（主存地址数 - 单芯片地址数）
- DRAM 的二维地址组织（省地址引脚 和 提高连续访问效率）
  - 先送行地址（行缓冲 `row buffer`，用 SRAM 实现），再送列地址
- 地址划分题的典型思路
  - 课件中的典型例子
    - `128MB` 的 DRAM 由 8 片 `16M x 8 bits` 芯片构成
    - 因为 `128MB = 2^27B`，所以主存地址共 27 位
    - 每片 `16M = 2^24` 个 8 位单元，所以片内地址是 24 位
    - 8 片并行工作时，一次可以拼出 8B，也就是 64 位
    - 于是主存地址低 3 位可以理解为 8 个字节中的偏移或第几个 byte lane
    - 剩余高 24 位对应芯片内部地址
    - 若行地址、列地址各 12 位，则片内地址可拆成：
      - 12 位行地址
      - 12 位列地址
- 数据对齐
  - 数据对齐：一次数据是否能在较少的主存访问中取出
  - 例：若主存一次最多读 64 位，也就是 8B
  - 一个 32 位 `int` 若放在地址 `8,9,10,11`
    - 这 4B 都落在同一个 8B 对齐块中
    - 只需要访问 1 次主存
  - 若它放在地址 `6,7,8,9`
    - 前 2B 在前一个 8B 块
    - 后 2B 在后一个 8B 块
    - 需要访问 2 次主存
  - 所以按边界对齐的价值在于：
    - 减少访问次数
    - 降低访存开销

- DRAM 芯片规格与行列位数计算
  - 若某 DRAM 芯片规格为 `2^n x b位`
  - 其存储阵列有 `r` 行、`c` 列
  - 则有：`2^n = r x c`
  - 芯片内地址位数是 `n`
  - 行地址位数是 `log2 r`
  - 列地址位数是 `log2 c`
  - 通常可理解为：
    - 高位作行地址
    - 低位作列地址
- 为什么行列位数不一定完全平均
  - 行列地址位数尽量接近，可以减少地址引脚，便于分时复用
  - 但 DRAM 需要按行刷新，若行数过多，刷新管理会更频繁
  - 所以实际设计是在引脚数、刷新代价、实现复杂度之间做折中

- 多模块存储器
  - 多模块存储器把主存分成多个 Bank，让它们同时或交替工作，提高吞吐率
  - 重点不是把单次访问延迟变得特别小，而是让连续访问的数据流出得更密
- 连续编址
  - 按高位地址划分模块
  - 前一段连续地址属于模块 0，后一段连续地址属于模块 1，以此类推
  - 优点：
    - 不同任务若访问不同模块，可以并行
  - 局限：
    - 对连续地址流的加速有限
    - 因为相邻地址可能长时间都落在同一个模块
- 交叉编址
  - 按低位地址划分模块
  - 例如 4 个 Bank 时：
    - 地址 0 在模块 0
    - 地址 1 在模块 1
    - 地址 2 在模块 2
    - 地址 3 在模块 3
    - 地址 4 又回到模块 0
  - 这样连续访问地址时，不同模块可以轮流启动
  - 当第一个模块还在处理时，第二、第三、第四个模块已经开始接手后续访问
  - 于是经过流水化重叠后，数据可以更密集地返回给 CPU
  - 课件中常说：4 体交叉时，理论上主存吞吐量可提高到约 4 倍
- 对交叉编址的直观理解
  - 像有多个窗口同时处理连续到来的请求
  - 如果连续任务轮流分配给不同窗口，整体完成速率会高很多
  - 但若访问模式不连续，或者频繁跳转到同一个 Bank，对并行性的利用就会下降

## 三、

- 程序和数据通常长期保存在外存中，运行时再调入主存
- 典型代表是磁盘
  - 盘面上有很多同心圆，每个同心圆叫磁道 `track`
  - 每个磁道再分成很多小段，每段叫扇区 `sector`
  - 扇区是磁盘读写的基本单位
  - 多个盘面上半径相同的一组磁道合起来叫柱面 `cylinder`
  - 所以磁盘地址常见表示方法是：
    - 柱面号
    - 磁头号
    - 扇区号
- 提高磁盘容量的基本思路，核心是提高记录密度
    - 增加磁道数，也就是提高道密度
    - 增加每条磁道可记录的扇区数，也就是提高位密度
  - 机械硬盘访问要经历机械移动和旋转等待
  - 一个扇区的访问通常包括：
    - 寻道：磁头移动到目标磁道
    - 旋转等待：等待目标扇区转到磁头下方
    - 数据传输：真正把数据读出或写入
  - 平均访问时间：$T = 平均寻道时间 + 平均旋转等待时间(一般取转一圈的1/2) + 数据传输时间$
- SSD：固态硬盘

- 磁盘和主存之间：DMA（由CPU控制）
- DMA：直接存储器存取
  - `DMA = Direct Memory Access`
  - 核心思想：
    - 外设和主存之间直接传输数据
- 读一个磁盘扇区的 DMA 流程
    - 第一步：CPU 初始化磁盘控制器
      - 发出读命令
      - 给出磁盘逻辑块号
      - 给出主存起始地址
    - 第二步：磁盘控制器找到目标扇区，并通过 DMA 把数据送入主存
    - 第三步：传输结束后，磁盘控制器发中断通知 CPU
  - 所以 CPU 主要管“启动”和“收尾”，中间的大块数据搬运由 DMA 完成
- DMA 的总线争用
  - DMA 和 CPU 会争用总线
  - DMA 通常优先级较高
  - 因为高速外设的数据如果不能及时搬走，可能会丢失
- DMA 的三种传送方式
  - CPU 停止法
    - 特点：实现简单，但对 CPU 影响最大
  - 周期挪用法
    - 可以理解成 DMA “插队”一个存储周期
    - 特点：兼顾 I/O 实时性和 CPU 运行，是很常见的思路
  - 交替分时访问法
    - 把主存周期预先分成两个时间片

- 检错/纠错的一般过程
  - 设原始数据位为 `M`
  - 根据某个规则生成校验位 `P`
  - 把 `M` 和 `P` 一起存储或传输
  - 读出后得到新的数据 `M'` 和原校验位
  - 系统再根据 `M'` 重新计算校验结果
  - 再和原校验位比较
  - 可能出现三种结果：
    - 没检测到错误，直接输出
    - 检测到错误且能纠正，则纠错后输出
    - 检测到错误但无法确定错误位置，则报告出错

- 码字、码距与检错纠错能力
  - 数据位和校验位合起来形成一个完整的码字
  - 两个码字对应位中不同位的个数，叫它们之间的距离
  - 一种编码方案中任意两个合法码字的最小距离，叫**码距**
  - 码距越大，检错和纠错能力越强
  - 课件里常用的结论要记住：
    - 若码距 `d` 为奇数
      - 可发现 `d - 1` 位错
      - 或纠正 `(d - 1) / 2` 位错
    - 若码距 `d` 为偶数
      - 可发现 `d / 2` 位错
      - 并纠正 `d / 2 - 1` 位错
  - 复习时更常用的一条统一结论也可以记：
    - 若要纠正 `t` 位错，需满足 `d >= 2t + 1`
    - 若要发现 `s` 位错，需满足 `d >= s + 1`

- 奇偶校验
    - 只能可靠发现奇数位错误中的 1 位错等情况
    - 若同时错了 2 位，奇偶性可能恢复原状，从而漏检

- 海明码 Hamming Code（*）
  - 海明码的核心目标是：
    - 不只是发现错
    - 还要能定位哪一位错了
  - 做法是把数据位和多个校验位组合成一个码字
- 海明码课件中的典型例子
  - 8 位数据 + 4 位校验位 = 12 位码字
  - 4 个校验位放在第 `1、2、4、8` 位
  - 数据位放在其余位置
  - 这种码的最小码距是 `3`
  - 所以它的能力是：
    - 可纠正 1 位错
    - 可发现 2 位错
  - 这类码常称为单纠错码 `SEC`

- SEC-DED（*）
  - `SEC-DED = Single Error Correction, Double Error Detection`
  - 含义是：
    - 单比特错误可纠正
    - 双比特错误可检测
  - 要做到这一点，码距需要扩大到 `4`
  - 通常做法是在海明码基础上再增加 1 位总校验位
  - 这是存储系统里非常典型的一类 ECC 思路
  - 因为对内存来说，最理想的状态就是：
    - 单 bit 错自动修正
    - 双 bit 错至少能报警

- CRC：循环冗余校验
  - CRC 常用于大批量数据存储和传输

## 四、

- **Cache 是在 CPU 和主存之间加速**
- **虚拟存储器是在主存和磁盘之间扩展、保护和管理**
- Cache 的作用
  - CPU 访问内存非常频繁
  - 如果每次都直接访问主存，CPU 会被主存速度拖慢
  - 所以在 CPU 和主存之间放一个很小但很快的存储器，这就是 Cache
  - Cache 一般用 SRAM 做，容量不大，但速度接近 CPU
  - CPU 取指或读写数据时，先查 Cache
    - 若命中，直接从 Cache 取
    - 若不命中，再访问主存
- Cache 能发挥作用，根本原因是程序访问具有局部性（空间+时间）
- Cache 的基本组织
  - 主存按块 `Block` 划分
  - Cache 按行 `Line` 划分
  - 一个主存块装入一条 Cache 行
  - CPU 访问某个地址时，先判断该地址所在的主存块是否已经在 Cache 中
    - 在，叫 `hit`
    - 不在，叫 `miss`
  - `miss` 时要把整个主存块从主存调入 Cache

- Cache 性能指标
  - `Hit Rate`：命中率
  - `Miss Rate`：缺失率，通常有：
  - `Hit Time`：命中时间
  - `Miss Penalty`：缺失损失，也就是 miss 后额外付出的代价
  - 平均访问时间：$T = T_C + (1 - H)T_M$
  - 其中：
    - `T_C`：Cache 命中时间
    - `H`：命中率
    - `T_M`：miss 后访问主存等带来的额外时间
- Cache 地址字段划分
```text
[ Tag 标记 ][ Index 行号/组号 ][ Offset 块内偏移 ]
```

  - `Offset`
    - 决定该地址在块内的第几个字节
    - 若块大小为 `B` 字节，则：

```text
Offset 位数 = log2(B)
```

  - `Index`
    - 决定去 Cache 的哪一行或哪一组查找
  - `Tag`
    - 是剩余高位
    - 用于判断当前这行/这组中的内容是否真的是要找的那个主存块

- 直接映射 Direct Mapped
  - 一个主存块只能映射到 Cache 的唯一一行
    - 冲突缺失较多
  - 若 Cache 总容量为 `C`，块大小为 `B`
  - 则 行数 = C / B

  - 若主存地址总位数为 `m`
  - 则：

```text
Offset = log2(B)
Index = log2(C / B)
Tag = m - Index - Offset
```

- 直接映射的典型题
  - 例：32 位主存地址，1KB Cache，块大小 32B，直接映射
  - 先算块内偏移：

```text
Offset = log2(32) = 5 位
```

  - 再算 Cache 行数：

```text
1KB / 32B = 1024 / 32 = 32 行
```

  - 所以：

```text
Index = log2(32) = 5 位
Tag = 32 - 5 - 5 = 22 位
```

  - 地址字段划分为：

```text
[ 22位 Tag ][ 5位 Index ][ 5位 Offset ]
```

- 全相联 Fully Associative
  - 一个主存块可以放到 Cache 任意一行
  - 因为任意行都可以放，所以没有 `Index`
  - 访问时要把地址中的 `Tag` 与所有 Cache 行的 Tag 同时比较
  - 优点：
    - 冲突缺失最少
  - 缺点：
    - 比较器多
    - 硬件复杂
    - 命中时间较长

- 组相联 Set Associative
  - 是直接映射和全相联的折中
  - Cache 先分组
  - 一个主存块只能映射到某个固定组，但在组内可以放到任意一路
  - 课件常说：
    - 组间模映射
    - 组内全映射
  - 常用关系式：

```text
Cache 组号 = 主存块号 mod Cache 组数
```

  - 若是 `n` 路组相联
    - 表示每组有 `n` 行
  - 组数计算：

```text
组数 = Cache 总行数 / n
```

- 4 路组相联的典型题
  - 还是：32 位主存地址，1KB Cache，块大小 32B
  - Cache 总行数仍是 32 行
  - 若改成 4 路组相联，则：

```text
组数 = 32 / 4 = 8 组
```

  - 所以：

```text
Offset = log2(32) = 5 位
Index = log2(8) = 3 位
Tag = 32 - 5 - 3 = 24 位
```

  - 地址字段划分变为：

```text
[ 24位 Tag ][ 3位 Set Index ][ 5位 Offset ]
```

- 三种映射方式怎么记
  - 直接映射：只能住指定房间，找得快，但容易冲突
  - 全相联：哪个房间都能住，冲突少，但查找贵
  - 组相联：只能住指定楼层，但楼层里有多个房间可选，是折中方案
- 映射方式与性能关系
  - 在 Cache 大小和块大小固定时：
    - 缺失率通常：直接映射最高，全相联最低
    - 命中时间通常：直接映射最短，全相联最长
  - 组相联一般处于中间

- Cache 的写策略
  - 读 Cache 相对简单
  - 写 Cache 要处理一致性问题
  - 因为 Cache 中只是主存块的副本
  - CPU 改了 Cache 后，主存中的对应内容如何保持一致，就是写策略要解决的问题

- 写命中：Write Through 与 Write Back
  - `Write Through` 写直达
    - CPU 写 Cache 的同时，也立刻写主存
    - 优点：
      - 主存内容始终较新
      - 控制简单
    - 缺点：
      - 每次写都要碰主存，速度慢
    - 所以常配合 `Write Buffer` 写缓冲
      - 写缓冲通常是 FIFO 队列
      - 若频繁写入，写缓冲可能饱和，导致阻塞
  - `Write Back` 写回
    - CPU 先只改 Cache
    - 不立即写主存
    - 同时把该 Cache 行标记为 `dirty`
    - 等这一行将来被替换出去时，如果 `dirty = 1`，再写回主存
    - 优点：
      - 减少主存写次数
    - 缺点：
      - 控制更复杂
      - 主存内容可能暂时不是最新

- 写不命中：Write Allocate 与 No Write Allocate
  - `Write Allocate` 写分配
    - 先把对应主存块调入 Cache
    - 再在 Cache 中执行写操作
  - `No Write Allocate` 非写分配
    - 不把块调入 Cache
    - 直接把数据写到主存
  - 常见搭配：
    - `Write Back + Write Allocate`
    - `Write Through + No Write Allocate`
  - 但具体题目还是以题设为准

- 虚拟存储器
  - 现在把视角从“CPU 和主存之间”再往外推一层
  - 虚拟存储器是主存和磁盘之间的层次
  - 它不是为了单纯加速，而是为了：
    - 扩展地址空间
    - 实现保护
    - 支持共享
    - 便于管理
  - 每个进程都看到一个很大的、连续的、私有的虚拟地址空间

- 虚拟地址与物理地址
  - 程序中使用的是虚拟地址 `VA`
  - 真正主存中使用的是物理地址 `PA`
  - CPU 发出虚拟地址后，要经过地址转换才能得到物理地址
  - 虚拟地址通常分成：
    - `VPN`：虚拟页号
    - `VPO`：页内偏移
  - 物理地址通常分成：
    - `PPN`：物理页框号
    - `PPO`：页内偏移
  - 因为页大小相同，所以：

```text
VPO = PPO
```

  - 地址转换的本质就是：
    - 保持页内偏移不变
    - 把 `VPN` 映射成 `PPN`

- 页大小与位数计算
  - 若页大小为 `64B`
  - 则页内偏移位数：

```text
log2(64) = 6 位
```

  - 若虚拟地址共 14 位
  - 则：

```text
VPN 位数 = 14 - 6 = 8 位
```

  - 所以虚拟页数为：

```text
2^8 = 256
```

  - 页表项数也就是 256 项
  - 这一类题的套路就是：
    - 先由页大小求偏移位数
    - 再从总地址位数中扣掉偏移位数，得到页号位数

- 页表
  - 页表是虚拟页号到物理页框号的映射表
  - 每个进程通常有自己的页表
  - 页表首址通常由页表基址寄存器保存
  - 一个页表项中常见的信息有：
    - `Valid` 装入位
    - `Dirty` 修改位
    - 替换控制位
    - 访问权限位
    - 禁止缓存位
    - 实页号 `PPN`
  - 若 `Valid = 0`
    - 说明该页当前不在主存
    - 会触发缺页
  - 若访问不符合权限
    - 会触发保护异常

- 缺页 Page Fault
  - 虚拟地址对应的页可能不在主存，而在磁盘上
  - 这时页表项 `Valid = 0`
  - CPU 产生缺页异常
  - 操作系统接管处理：
    - 从磁盘把需要的页调入主存
    - 更新页表
    - 必要时替换旧页
    - 然后恢复程序执行
  - 缺页代价非常大
  - 因为它涉及访问磁盘，而磁盘是 ms 级
  - 所以页命中率在虚拟存储器中非常重要
  - 也因为缺页代价太高，虚拟存储器通常更偏向减少缺页，而不是只追求一点点查找速度

- 为什么虚拟页到主存页框常近似看成全相联
  - 任意虚拟页在装入时，通常可以放到任意空闲物理页框
  - 所以从“映射自由度”上看，更像全相联思想
  - 同时虚拟存储器通常采用 `Write Back`
  - 因为若每次写都立即写磁盘，代价太高

- TLB 快表
  - 如果每次访存都先去主存查页表，再去主存取数据，会非常慢
  - 所以要用 `TLB`（Translation Lookaside Buffer）
  - TLB 本质上是“页表项的 Cache”
  - 也就是把最常用的页表项放到很快的小硬件中
  - 这样就能减少访问主存页表的次数
- TLB 的查找
  - CPU 给出虚拟地址后，先用 `VPN` 查 TLB
  - 若 TLB 命中
    - 直接得到 `PPN`
    - 再与页内偏移拼成物理地址 `PA`
  - 若 TLB 缺失
    - 再去主存中的页表查
  - 全相联 TLB
    - 没有 index
    - `VPN` 要与所有项的 Tag 比较
  - 组相联 TLB
    - 虚页号高位作 Tag
    - 低位作 index

- 一次完整访存过程
  - 第一步：CPU 产生虚拟地址 `VA`
  - 第二步：先查 TLB
    - 若 TLB 命中，得到 `PPN`
    - 拼上页内偏移，得到物理地址 `PA`
  - 第三步：若 TLB 缺失，则去主存中的页表查页表项
    - 若页表项 `Valid = 1`
      - 说明该页在主存中
      - 可更新 TLB
      - 再得到物理地址 `PA`
    - 若页表项 `Valid = 0`
      - 发生缺页
      - 由操作系统从磁盘调页
  - 第四步：得到物理地址后，再去 Cache 查数据
    - Cache 命中则直接返回
    - Cache 缺失则从主存把块调入 Cache
- 三种常见 miss
  - `Miss1`：TLB 缺失
  - `Miss2`：缺页
  - `Miss3`：物理地址对应的数据不在 Cache 中
  - 处理层次不同：
    - TLB 缺失：硬件或操作系统处理
    - Cache 缺失：一般由硬件处理
    - 缺页：由操作系统处理

- TLB、页表、Cache 分别在查什么
  - 这是非常容易混淆的地方
  - TLB 查的是：
    - `VPN` 能否快速翻译成 `PPN`
  - 页表查的是：
    - 这个虚拟页到底映射到哪个物理页框
    - 或者它现在是否还在磁盘上
  - Cache 查的是：
    - 某个物理地址对应的数据块是否已经在高速缓存中
  - 所以三者不是一个层次上的同一件事
    - TLB 管地址翻译加速
    - 页表是完整映射依据
    - Cache 管数据访问加速

- Cache 和虚拟存储器放在一起比较
  - Cache - 主存层次
    - 数据单位通常是较小的块 `block`
    - 缺失代价是再访问主存
    - 一般由硬件自动处理
    - 主要目标是加速
  - 主存 - 磁盘层次
    - 数据单位通常是较大的页 `page`
    - 缺页代价是访问磁盘
    - 一般由操作系统处理
    - 主要目标是扩展地址空间、保护、共享和管理
  - 页通常比 Cache block 大得多
  - 缺页开销也比 Cache miss 大得多
  - 所以虚拟存储器比 Cache 更强调页命中率

- 第四讲最后收成几句话
  - Cache 利用局部性，在 CPU 和主存之间保存活跃主存块
  - 地址划分时：
    - `Offset` 由块大小决定
    - `Index` 由 Cache 行数或组数决定
    - `Tag` 是剩余高位
  - 直接映射只有一个可能位置，快但冲突多
  - 全相联最灵活，冲突少但硬件复杂
  - 组相联是折中
  - 写策略中：
    - 写直达简单，但写主存多
    - 写回减少主存写次数，但需要 `dirty` 位
  - 虚拟地址分 `VPN + VPO`
  - 物理地址分 `PPN + PPO`
  - 页内偏移保持不变，即 `VPO = PPO`
  - 页表保存 `VPN -> PPN` 的完整映射
  - TLB 缓存常用页表项，用于加速地址转换
  - 一次访存可能经历：
    - TLB 缺失
    - 缺页
    - Cache 缺失
  - 其中缺页代价最大，由操作系统处理
